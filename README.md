# ДЭ-2027 — платформа подготовки к демоэкзамену

Полноценная учебная платформа с сервером: аккаунты, база данных, серверный прогресс, **практикум с редактором кода и проверкой решений**, **аудит реального Laravel-проекта по критериям КИМ**, заметки, админка и редактирование уроков. Стек — **Laravel 13 + SQLite**, то есть тот же, который нужен на демоэкзамене 09.02.07.

Курс внутри — 9 модулей, 46 уроков и **14 лабораторных**: от терминала и первого PHP-файла до Laravel, заявок, статусов, админки и мобильного макета 390×844. Материал сверен с КИМ 09.02.07-3-2027 (ГИА ДЭ БУ): 3 ч 30 мин, 75 баллов, три задания.

## Быстрый запуск

```bash
cd C:\Users\Dqavo\Desktop\demo-exam-platform
composer install
copy .env.example .env
php artisan key:generate
php artisan migrate:fresh --seed
php artisan serve --host=127.0.0.1 --port=8100
```

Откройте <http://127.0.0.1:8100>.

Можно дважды щёлкнуть `start.bat` — он поднимет сервер и откроет браузер. При первом запуске база заполнится уроками и аккаунтами; повторный запуск не перезаписывает контент и пароли.

### Настольное приложение (EXE)

Собранная версия лежит в `dist\DE-2027\`. Запуск — `dist\DE-2027\Запуск.bat` или `dist\DE-2027\DE-2027.exe`.

Это **нативное окно Windows** (WinForms + WebView2), а не ярлык на браузер: нет адресной строки, вкладок и внешнего Chromium. Внутри окна — платформа, которую обслуживает встроенный PHP 8.5 и SQLite. Установка, терминал и интернет не нужны. При закрытии окна сервер останавливается.

При первом запуске приложение копируется в `%APPDATA%\DE-2027\app`, поэтому папку с EXE можно переносить и обновлять, не теряя прогресс. При новой сборке код синхронизируется по `version.txt`, миграции применяются автоматически, а база, аккаунты и прогресс остаются на месте. База и логи живут в `%APPDATA%\DE-2027\app\storage\logs\desktop.log`.

Требование: **Microsoft Edge WebView2 Runtime**. На Windows 10/11 он обычно уже установлен (входит в Edge). Если окно не открывается — поставьте Evergreen Runtime с сайта Microsoft.

Пересобрать:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-portable.ps1
```

Ограничения сборки:

- Windows x64, ~244 МБ.
- Нужен WebView2 Runtime; без него окно не отрисуется.
- EXE не подписан: SmartScreen может показать предупреждение.
- Папку можно переносить целиком, но нельзя переименовывать `app` и `runtime`.
- Порт 8100, при занятости — 8101–8120.
- Логи: `%APPDATA%\DE-2027\app\storage\logs\desktop.log`.

## Практикум

14 лабораторных: HTML, CSS, Bootstrap, PHP, PDO, SQL, миграции Laravel, валидация, вход, Blade, статусы, мобильный экран и чек-лист сдачи.

- Студент пишет решение в редакторе и отправляет на проверку.
- PHP проходит `php -l` (синтаксис) и проверки по обязательным конструкциям.
- SQL выполняется на учебной SQLite-базе с фикстурой `users / rooms / applications`; проверяются колонки и строки.
- HTML/Blade проверяются по обязательным тегам, классам и директивам.
- Результат — список критериев с сообщением, что именно поправить.
- Решение открывается после успешной проверки; подсказки доступны сразу.
- Черновик сохраняется на сервере.
- Код не исполняется на сервере: PHP только линтуется, SQL работает в памяти с `PRAGMA query_only`.

## Тренажёр

`/drills` — ежедневная практика в формате «реши вариант и иди дальше».

- **33 варианта** по шести направлениям: HTML-карточки, адаптивные сетки CSS, формы Bootstrap/Blade, валидация на PHP, SQL-запросы и Laravel-фрагменты.

- У каждого варианта — ориентир по времени, чтобы привыкать к темпу экзамена.

Данные: `drills`, `drill_attempts`, `drill_progress`. Логика очереди и повторов — `app/Http/Controllers/DrillController.php`, наполнение — `database/seeders/DrillSeeder.php`.

## Проверка проекта

`/capstone` — аудит реального проекта перед сдачей.

- Укажите локальную папку с `artisan` или HTTPS-ссылку на репозиторий (клон через git).
- Платформа читает файлы и проверяет 27 признаков по 8 группам критериев КИМ: каркас, маршруты, безопасность, ER, дизайн, мобильный макет, адаптив, валидацию, фильтры, Git.
- Максимум — 75 баллов, как в КИМ. Это **предварительная** оценка по статическому анализу.
- Результат сохраняется в историю; администратор видит его в разделе «Капстоун».
- Галочка **«Запустить проект»** включает глубокую проверку: временная SQLite, `migrate:fresh --seed`, `php artisan test`, запуск сервера и HTTP-сценарий (регистрация → вход → заявка → кабинет → защита админки → вход администратора).
- Локальный путь ограничен папками Desktop, Documents и `storage/app/projects`.
- Код проекта не запускается без галочки: без неё только чтение файлов. С галочкой код выполняется в папке проекта, но база подменяется на временную; реальная база не затрагивается.
- Ссылка на деплой сохраняется, но не открывается автоматически.

### Глубокая проверка

Если поставить галочку «Запустить проект», платформа:

1. создаёт временную SQLite и проверяет, что проект действительно переключился на неё;
2. выполняет `php artisan migrate:fresh --seed`;
3. запускает `php artisan test` на отдельной тестовой базе;
4. пересоздаёт временную базу после тестов;
5. поднимает `php artisan serve` на свободном порту;
6. проходит HTTP-сценарий: регистрация → вход → заявка → кабинет → защита админки → вход администратора;
7. останавливает сервер и удаляет временные файлы.

Реальная база проекта не затрагивается: перед миграциями проверяется путь SQLite. Сценарий рассчитан на типовые маршруты и таблицы; для проекта с другими именами часть шагов не пройдёт. Код проекта исполняется только при явной галочке.

## Своя тема и проект по теме

Два связанных раздела для случая, когда тема отличается от примеров КИМ.

**`/topic` — ТЗ под свою тему.** Вводите предметную область и получаете сущности, поля, статусы, маршруты и чек-лист. Скачивается как Markdown. Это только техническое задание, без кода.

**`/blueprint` — проект по теме целиком.** Введите тему — например, «Пицца на районе» или «Обмен книгами» — и генератор соберёт:

- **11 глав на 4 часа**: каркас, миграции, модели, маршруты и роли, регистрация и вход, заявки, отзывы, админка, дизайн и адаптив, сиды и тесты, приёмка.
- **Команды** для каждой главы и **полный код каждого файла** — 39 файлов, около 2 700 строк.
- **Проверки** после каждого шага и **типичные ошибки** с причиной.
- **Чек-лист 75 баллов** и **речь для защиты** с вопросами и ответами.
- **Готовый архив `.zip`**: 39 файлов проекта, которые распаковываются поверх свежего Laravel.

Пустые поля формы заполняются по теме: пресеты знают около 24 предметных областей, от пиццы и книг до автосервиса и клининга. Незнакомая тема тоже собирается — просто с нейтральными формулировками. Всё, что попадает в код, очищается от кавычек, угловых скобок и управляющих символов.

Шаблоны проекта лежат в `resources/blueprints/` как настоящий код с токенами `@@PROJECT@@`, `@@OBJECT@@` и другими. Логика — `app/Support/Blueprint.php` и `app/Http/Controllers/BlueprintController.php`.

Сгенерированный проект проверен целиком: миграции и сиды проходят, **13 тестов** зелёные, браузерный сценарий (регистрация → заявка → три статуса → отзыв) работает, на 390 / 768 / 1440 px нет горизонтальной прокрутки.

**Веб-версия без установки:** <https://itachqk.github.io/de-2027/> — тот же генератор на GitHub Pages, открывается с телефона. PHP на Pages не работает, поэтому движок подстановки портирован на JavaScript: `docs/` собирается скриптом `tools/export-web.php`, а `.md` из браузера побайтово совпадает с `.md` из Laravel-версии. Архив собирается прямо в браузере.

## Как устроен прогресс

Состояние пользователя — JSON в таблице `user_states`:

```json
{
  "done": { "exam-format": true },
  "checks": { "exam-format": { "0": true } },
  "quiz": { "exam-format:0": { "picked": 1, "checked": true } },
  "notes": { "exam-format": "Заметка" },
  "last": "exam-format",
  "timer": { "endsAt": 0, "remaining": 12600000, "running": false }
}
```

SPA отправляет состояние на `POST /api/state` с CSRF-токеном. Гость пишет в `localStorage` и не смешивается с аккаунтом. После входа серверное состояние имеет приоритет.

## API

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/course` | все | модули, уроки, рецепты |
| GET | `/api/state` | авторизованные | состояние пользователя |
| POST | `/api/state` | авторизованные | сохранить состояние |

## Контент

Уроки лежат в базе. Источник для сидера — `database/seeders/data/course.json`, он собран из статического тренажёра:

```bash
node tools/export-course.mjs
php artisan db:seed --class=CourseSeeder
```

Формат блока:

```json
{ "t": "p", "v": "Текст с `кодом`." }
{ "t": "code", "lang": "php", "file": "routes/web.php", "v": "..." }
{ "t": "table", "head": ["Метод", "URL"], "rows": [["GET", "/login"]] }
```

Допустимые типы: `p`, `h`, `h4`, `quote`, `ul`, `ol`, `file`, `note`, `warn`, `ok`, `goal`, `code`, `table`, `steps`.

В админке блоки и вопросы редактируются как JSON. Невалидный JSON не сохраняется — форма вернёт ошибку.

## Безопасность

- Пароли — `Hash::make`, в модели каст `hashed`.
- CSRF на всех POST/PUT/DELETE, включая `/api/state`.
- Роль `admin` проверяется middleware, а не ссылкой в меню.
- Регистрация всегда создаёт `student`; роль нельзя подменить формой.
- `/api/state` принимает только авторизованного пользователя и ограничивает размер JSON.
- Логин и регистрация ограничены по частоте (`throttle`).
- Экранирование вывода в SPA; JSON уроков выводится через безопасный рендер блоков.

## Ограничения

- Это локальная платформа, не облачный сервис: SQLite, один сервер, без очередей.
- Настольная сборка — Windows x64 и требует WebView2 Runtime; macOS/Linux не поддерживаются.
- EXE не подписан сертификатом: SmartScreen может показать предупреждение при первом запуске.
- Нет восстановления пароля по email (почта в `.env` настроена в `log`).
- Нет загрузки файлов и аватаров.
- Практикум проверяет синтаксис PHP и обязательные конструкции, но не запускает ваш PHP-код. SQL выполняется только как SELECT на учебной базе в памяти.
- Капстоун — статический аудит файлов: он может ошибаться в обе стороны и не заменяет эксперта. Глубокая проверка запускает код проекта на временной базе; для чужих проектов это делайте только на своей машине. Клонирование репозитория требует git и сети.
- Глубокий сценарий рассчитан на типовые маршруты `/register`, `/login`, `/profile`, `/application`, `/admin` и таблицы `users`/`rooms`/`applications`; в проекте с другими именами часть шагов не пройдёт.
- Прогресс и сдачи можно подделать через API — это учебный тренажёр, а не экзаменационная система с прокторингом.
- Контент — авторская интерпретация КИМ; формулировки своего варианта сверяйте с комплектом.
- Статический тренажёр `demo-exam-trainer` остаётся отдельной офлайн-версией без аккаунтов.

## Если что-то не запускается

```bash
php artisan optimize:clear
php artisan migrate:fresh --seed
php artisan serve --port=8101
```

- `Invalid URI: Host is malformed` — проверьте `APP_URL` в `.env`, он должен быть `http://127.0.0.1:8100`.
- `no such table` — выполните `php artisan migrate`.
- `419 Page Expired` — обновите страницу, проверьте `APP_KEY` и `SESSION_DRIVER=database`.
- Порт занят — запустите на другом порту и поправьте `APP_URL`.
